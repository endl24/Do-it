### 선택 이유
- **Flutter**: 하나의 UI 코드로 Android·iOS에 같은 화면이 나와 UI 설계서대로 만들기 쉽고, 화면 단위로 작업을 나누기 좋습니다. Firebase와 ML Kit 모두 Flutter 패키지를 제공합니다.
- **SQLite** (대안: shared_preferences, Hive, drift): 할 일은 여러 필드를 가진 기록이고 한 건씩 수정·삭제하므로, 한 행만 바꿀 수 있는 표 저장이 알맞습니다. 자세한 비교는 [로컬 저장 방식 비교](#로컬-저장-방식-비교)에 있습니다.
- **Firebase** (대안: Supabase): Firestore가 기기 캐시와 대기 쓰기를 기본으로 제공해, 오프라인에서 쓴 할 일을 연결이 돌아오면 자동으로 서버에 반영합니다. 아직 반영되지 않은 항목은 `hasPendingWrites`로 구분해 '동기화 대기'로 표시할 수 있습니다. Supabase는 같은 동작을 위해 대기 큐와 재전송·병합 로직을 직접 만들어야 합니다.
- **ML Kit**: 글자 인식과 마감일 추출을 모두 지원하고 Android·iOS에서 동작합니다. 한국어 모델이 내장되어 있어 모델을 직접 넣을 필요가 없고, 기기 안에서 무료로 동작해 오프라인에서도 쓸 수 있습니다.
- **Firebase AI Logic**: 이미 쓰는 Firebase 프로젝트에 바로 연결되어 앱에 API 키를 넣지 않아도 되고, 이미지도 입력으로 보낼 수 있어 인식 실패 시 재인식까지 처리할 수 있습니다.

### 로컬 저장 방식 비교
할 일은 `do_it.db` 파일의 `todos` 표에 한 건이 한 행으로 저장됩니다. 한 건은 제목, 중요도, 긴급도, 완료 여부, 마감일, 알림 사용, 등록 경로, 동기화 상태 등 12개 필드를 가집니다.

| 방식 | 저장 형태 | 이 앱에 쓸 때 | 판단 |
| --- | --- | --- | --- |
| **SQLite** (`sqflite`) | 표와 SQL | 필드를 열로 나눠 저장하고, id로 한 건만 덮어쓰거나 지웁니다. 표 정의와 변환 코드는 직접 작성합니다. | **선택** |
| shared_preferences | 키-값 (`int`, `double`, `bool`, `String`, `List<String>`) | 할 일을 JSON 문자열로 바꿔 넣어야 합니다. 공식 문서가 쓰기 완료를 보장하지 않으니 중요한 데이터에 쓰지 말라고 안내합니다. | 설정값에는 맞지만 할 일 목록에는 맞지 않음 |
| Hive | 박스 단위 키-값 | id를 키로 한 건씩 저장할 수 있지만, 객체마다 어댑터가 필요하고 쿼리 기능이 없습니다. `hive`의 마지막 안정 버전은 약 4년 전 출시되었고(2026년 11월 확인), 커뮤니티 포크 `hive_ce`가 따로 있습니다. | 조회 기능과 유지보수가 아쉬움 |
| drift | SQLite 위의 라이브러리 | 타입 검사되는 쿼리와 스키마 변경 지원이 좋지만, 표 정의에서 코드를 생성하는 단계가 추가됩니다. | 쿼리가 적은 지금은 과함 |

- **선택 이유:** 수정·완료·삭제가 모두 한 건 단위라 한 행만 바꾸면 됩니다. 앞으로 동기화 대기 항목(A20–A26)이나 날짜별 할 일처럼 조건에 맞는 항목만 고를 때 SQL을 쓸 수 있습니다.
- **지금의 한계:** 전체·미완료·완료 필터와 화면 정렬은 불러온 목록을 앱 코드에서 처리합니다. 따라서 현재 기능만 보면 SQL 조회의 이점은 아직 크지 않습니다.
- **감수하는 점:** 표 구조를 바꾸면 데이터베이스 버전을 올리고 기존 데이터를 옮기는 코드를 작성해야 합니다. 아직은 첫 버전이라 이 코드가 없습니다.
- **교체 가능성:** `TodoController`는 `TodoRepository` 인터페이스만 사용합니다. 저장 방식을 바꾸면 저장소 구현과 그것을 만드는 `todo_list_screen.dart`의 한 줄만 고치면 됩니다.
- **확인 방법:** `app/test/services/sqlite_todo_repository_test.dart`가 연결을 닫았다 다시 연 뒤에도 값이 남는지 검사합니다(`flutter test`). iPhone 시뮬레이터에서도 앱을 완전히 종료했다가 다시 실행해 확인했습니다.

### 원칙
- 외부 서비스는 무료 요금제 안에서만 사용합니다.
- 사진 글자 인식은 기기 안에서 처리하고 사진을 외부로 보내지 않습니다.
- 클라우드 AI는 온라인이고 사용자가 요청했을 때만 호출하며, 실패하면 기기에서 처리한 결과를 그대로 씁니다.

## 구현 기능
### MP1 — 화면과 상태 관리
- **할 일 목록:** 등록한 할 일을 카드 목록으로 보여 주고, 남은 할 일 개수를 표시합니다.
- **할 일 추가:** [할 일 추가] 버튼으로 입력 시트를 열어 등록합니다. 제목은 필수이며 100자까지 입력할 수 있습니다.
- **완료 토글:** 체크박스를 누르면 완료 상태가 바로 바뀝니다. 완료한 할 일은 취소선으로 표시되고 목록 아래로 내려가며, 남은 개수도 함께 바뀝니다.
- **빈 상태 안내:** 등록한 할 일이 없으면 안내 문구와 등록 방법을 보여 줍니다.

### MP2 — 로컬 저장
- **데이터 유지:** 할 일을 SQLite에 저장해 앱을 다시 켜도 유지합니다.
- **수정·삭제:** 카드를 눌러 연 상세 화면에서 수정하고 삭제합니다. 삭제 전에 확인하며, 삭제 직후 실행 취소할 수 있습니다.
- **필터:** 전체·미완료·완료로 목록을 전환합니다.

### 그 밖의 할 일 기능
- **상세 화면:** 마감일, 남은 기간, 등록 경로, 상태를 보여 주고 수정, 완료 표시, 삭제를 할 수 있습니다.
- **사분면 보기:** 할 일 탭 안에서 목록과 사분면 보기를 전환합니다. 카드를 길게 눌러 다른 영역으로 끌면 중요도와 긴급도가 바뀝니다.

### 아직 연결되지 않은 부분
- 일정·팀·설정 탭은 화면이 먼저 만들어져 있고, 할 일 데이터와 서버에는 아직 연결되어 있지 않습니다.
- 사진으로 할 일을 등록하는 화면(메모 촬영, 후보 검토, 인식 실패, 권한 안내)도 카메라·글자 인식과 아직 연결되어 있지 않습니다. 빈 상태의 [사진에서 가져오기] 버튼은 준비 중이라는 안내만 띄웁니다.
- 마감 알림은 켜고 끄는 값만 저장하며, 실제 알림은 아직 예약하지 않습니다.

## 화면 구성
| 화면 | 구성 |
| --- | --- |
| 하단 탭 | 앱의 첫 화면. 할 일·일정·팀·설정 탭을 전환합니다. |
| 할 일 목록 | 제목과 남은 개수, 목록·사분면 전환, 필터, 할 일 카드(체크박스, 제목, 사분면 태그, 마감 표시), [할 일 추가] 버튼 |

## 폴더 구조
```
app/lib/
├── main.dart           # 앱 시작점 (runApp만)
├── app.dart            # MaterialApp, 테마, 라우팅
├── core/
│   ├── constants/      # 상수 (색상 코드, 문자열, 키 값 등)
│   ├── theme/          # 앱 테마
│   └── utils/          # 공용 함수 (날짜 포맷 등)
├── models/             # 데이터 클래스 (예: todo.dart)
├── services/           # 외부 연동 (API, DB, 로컬 저장소)
├── widgets/            # 여러 화면에서 같이 쓰는 위젯
└── screens/            # 화면 단위 폴더
    ├── main/           # 하단 탭 틀 (할 일·일정·팀·설정)
    └── todo_list/
        ├── todo_list_screen.dart
        └── widgets/    # 이 화면에서만 쓰는 위젯
```

### 규칙
- 새 화면은 `screens/<화면이름>/<화면이름>_screen.dart`로 만들고, 클래스 이름은 `XxxScreen`으로 합니다.
- 한 화면에서만 쓰는 위젯은 그 화면 폴더의 `widgets/`에, 두 화면 이상에서 쓰면 `lib/widgets/`로 옮깁니다.
- 파일 이름은 `snake_case.dart`, 클래스 이름은 `PascalCase`로 씁니다.
- 화면 단위로 작업을 나누면 서로 다른 파일을 수정하게 되어 머지 충돌이 줄어듭니다.
- `app.dart`, `core/` 같은 공용 파일을 수정할 때는 팀원에게 먼저 알립니다.
