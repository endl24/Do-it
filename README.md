### 선택 이유
- **Flutter**: 하나의 UI 코드로 Android·iOS에 같은 화면이 나와 UI 설계서대로 만들기 쉽고, 화면 단위로 작업을 나누기 좋습니다. Firebase와 ML Kit 모두 Flutter 패키지를 제공합니다.
- **SQLite** (대안: shared_preferences, Hive, drift): 할 일은 여러 필드를 가진 기록이고 한 건씩 수정·삭제하므로, 한 행만 바꿀 수 있는 표 저장이 알맞습니다. 자세한 비교는 [로컬 저장 방식 비교](#로컬-저장-방식-비교)에 있습니다.
- **Firebase** (대안: Supabase): Firestore가 기기 캐시와 대기 쓰기를 기본으로 제공해, 오프라인에서 쓴 할 일을 연결이 돌아오면 자동으로 서버에 반영합니다. 아직 반영되지 않은 항목은 `hasPendingWrites`로 구분해 '동기화 대기'로 표시할 수 있습니다. Supabase는 같은 동작을 위해 대기 큐와 재전송·병합 로직을 직접 만들어야 합니다.
- **ML Kit (Android)·Vision (iOS)**: 둘 다 기기 안에서 무료로 동작해 비행기 모드에서도 글자를 읽습니다. Android는 ML Kit 한국어 모델의 번들판을 써서 모델이 앱에 들어 있고, 처음 실행할 때 내려받을 필요가 없습니다. iOS는 Flutter용 ML Kit 플러그인(`google_mlkit_text_recognition`)이 라틴 문자만 지원해 한국어를 읽지 못하므로, OS에 들어 있는 Apple Vision(`VNRecognizeTextRequest`, 한국어·영어)을 씁니다. 두 엔진은 같은 플랫폼 채널 `doit/text_recognition`으로 불러 Dart 코드는 하나입니다.
- **Firebase AI Logic**: 이미 쓰는 Firebase 프로젝트에 바로 연결되어 앱에 API 키를 넣지 않아도 되고, 이미지도 입력으로 보낼 수 있어 인식 실패 시 재인식까지 처리할 수 있습니다.

### 로컬 저장 방식 비교
할 일은 `do_it.db` 파일의 `todos` 표에 한 건이 한 행으로 저장됩니다. 한 건은 제목, 중요도, 긴급도, 완료 여부, 마감일, 알림 사용, 등록 경로, 동기화 상태 등 12개 필드를 가집니다.

| 방식 | 저장 형태 | 이 앱에 쓸 때 | 판단 |
| --- | --- | --- | --- |
| **SQLite** (`sqflite`) | 표와 SQL | 필드를 열로 나눠 저장하고, id로 한 건만 덮어쓰거나 지웁니다. 표 정의와 변환 코드는 직접 작성합니다. | **선택** |
| shared_preferences | 키-값 (`int`, `double`, `bool`, `String`, `List<String>`) | 할 일을 JSON 문자열로 바꿔 넣어야 합니다. 공식 문서가 쓰기 완료를 보장하지 않으니 중요한 데이터에 쓰지 말라고 안내합니다. | 설정값에는 맞지만 할 일 목록에는 맞지 않음 |
| Hive | 박스 단위 키-값 | id를 키로 한 건씩 저장할 수 있지만, 객체마다 어댑터가 필요하고 쿼리 기능이 없습니다. `hive`의 마지막 안정 버전은 약 4년 전 출시되었고(2026년 11월 확인), 커뮤니티 포크 `hive_ce`가 따로 있습니다. | 조회 기능과 유지보수가 아쉬움 |
| drift | SQLite 위의 라이브러리 | 타입 검사되는 쿼리와 스키마 변경 지원이 좋지만, 표 정의에서 코드를 생성하는 단계가 추가됩니다. | 쿼리가 적은 지금은 과함 |

- **선택 이유:** 수정·완료·삭제가 모두 한 건 단위라 한 행만 바꾸면 됩니다. 앞으로 동기화 대기 항목(A20–A26)이나 날짜별 할 일처럼 조건에 맞는 항목만 고를 때 SQL을 쓸 수 있습니다.
- **지금의 한계:** 전체·미완료·완료 필터와 화면 정렬은 불러온 목록을 앱 코드에서 처리합니다. 따라서 현재 기능만 보면 SQL 조회의 이점은 아직 크지 않습니다.
- **감수하는 점:** 표 구조를 바꾸면 데이터베이스 버전을 올리고 기존 데이터를 옮기는 코드를 작성해야 합니다. 아직은 첫 버전이라 이 코드가 없습니다.
- **교체 가능성:** `TodoController`는 `TodoRepository` 인터페이스만 사용합니다. 저장 방식을 바꾸면 저장소 구현과 그것을 만드는 `todo_list_screen.dart`의 한 줄만 고치면 됩니다.
- **확인 방법:** `app/test/services/sqlite_todo_repository_test.dart`가 연결을 닫았다 다시 연 뒤에도 값이 남는지 검사합니다(`flutter test`). iPhone 시뮬레이터에서도 앱을 완전히 종료했다가 다시 실행해 확인했습니다.

### 원칙
- 외부 서비스는 무료 요금제 안에서만 사용합니다.
- 사진 글자 인식은 기기 안에서 처리하고 사진을 외부로 보내지 않습니다.
- 클라우드 AI는 온라인이고 사용자가 요청했을 때만 호출하며, 실패하면 기기에서 처리한 결과를 그대로 씁니다.

## 서버 동기화
### 저장 구조
- **로그인 전:** 할 일을 기기의 SQLite(`do_it.db`)에만 저장합니다.
- **첫 로그인:** SQLite의 할 일을 같은 ID로 Firestore에 한 번 옮깁니다.
- **로그인 후:** Firestore의 `users/{uid}/todos/{할 일 ID}`에 저장하고, Firestore SDK의 오프라인 캐시를 기기 저장소로 씁니다. SQLite는 다시 로그아웃했을 때만 씁니다.
- 할 일 문서에는 마지막 수정 시각 `updatedAt`, 쓰기마다 새로 만드는 `operationId`, 삭제 여부 `deleted`가 함께 저장됩니다.

### 충돌 처리 방침
| 상황 | 처리 |
| --- | --- |
| 두 기기가 같은 할 일을 수정 | **최신 수정 우선.** `updatedAt`이 더 늦은 수정을 남깁니다. 더 오래된 수정은 앱이 저장 전에 막고, 서버 보안 규칙도 거부합니다. 시각이 같으면 서버에 나중에 도착한 쓰기를 남깁니다. |
| 한 기기는 삭제, 다른 기기는 수정 | **삭제 우선.** 문서를 지우지 않고 `deleted: true`와 삭제 토큰을 남기므로, 시각과 관계없이 나중에 도착한 수정이 삭제된 할 일을 되살리지 못합니다. 보안 규칙도 문서의 실제 삭제를 막습니다. |
| 삭제 직후 [실행 취소] | 그 기기가 받은 삭제 토큰을 함께 보낼 때만 복구합니다. 다른 기기가 다시 삭제해 토큰이 바뀌었으면 복구하지 않습니다. |
| 오프라인에서 작성·수정·삭제 | 기기 캐시에 먼저 저장해 화면에 바로 반영하고 `동기화 대기`로 표시합니다. 연결되면 SDK가 서버로 보내고, 서버 확인을 받으면 `동기화 완료`로 바뀝니다. 서버가 위 규칙으로 거부한 쓰기는 `동기화 완료`로 바뀌지 않고 대기 건수에 남습니다. |
| 첫 로그인 이관 | 서버에 같은 ID의 문서가 있으면 더 최신 값이나 삭제 기록을 남깁니다. 서버 저장을 모두 확인한 뒤에만 SQLite 원본을 지우고, 도중에 끊기면 원본을 남겨 두었다가 같은 계정으로 다시 로그인할 때 이어서 옮깁니다. 첫 이관은 온라인에서만 진행됩니다. |

- **한계:** 수정 시각은 각 기기의 시계로 정합니다. 기기 시계가 크게 틀리면 실제로는 먼저 한 수정이 남을 수 있으므로, 확인할 때는 두 기기 모두 자동 날짜·시간을 켭니다.
- 세부 동작과 확인 절차는 [Firestore 이관 확인](app/tool/firestore_migration_check.md)과 [동기화 상태 확인](app/tool/sync_status_check.md)에 있습니다.

### 백엔드 설정 절차
1. **프로젝트 만들기:** [Firebase 콘솔](https://console.firebase.google.com/)에서 프로젝트를 만듭니다. 무료 Spark 요금제로 충분합니다.
2. **앱 등록:** 같은 프로젝트에 Android 앱(패키지 이름 `com.example.do_it`)과 iOS 앱(번들 ID `com.example.doIt`)을 등록합니다. 앱은 `.env` 값으로 Firebase를 초기화하므로, 등록할 때 받는 `google-services.json`·`GoogleService-Info.plist`는 저장소에 넣지 않습니다.
3. **인증 켜기:** Authentication → 로그인 방법에서 이메일/비밀번호를 사용 설정합니다.
4. **Firestore 만들기:** Firestore Database에서 데이터베이스를 만듭니다. 프로덕션 모드(기본 거부)로 시작합니다.
5. **보안 규칙 적용:** 저장소 최상위의 `firestore.rules`를 Firestore → 규칙 탭에 붙여 넣고 게시합니다. 본인 계정(`users/{uid}`)의 할 일만 읽고 쓸 수 있고, 다른 경로는 모두 거부됩니다. Firebase CLI를 쓰면 저장소 최상위에서 아래처럼 적용할 수도 있습니다.
   ```bash
   firebase deploy --only firestore:rules --project <프로젝트 ID>
   ```
6. **`.env` 작성:** `app/.env.example`을 `app/.env`로 복사하고 값을 채웁니다.

   | 키 | 확인하는 곳 |
   | --- | --- |
   | `FIREBASE_PROJECT_ID` | 프로젝트 설정 → 일반의 프로젝트 ID |
   | `FIREBASE_MESSAGING_SENDER_ID` | 프로젝트 설정 → 일반의 프로젝트 번호 |
   | `FIREBASE_ANDROID_API_KEY`, `FIREBASE_ANDROID_APP_ID` | Android 앱의 API 키와 앱 ID (`google-services.json`의 `current_key`, `mobilesdk_app_id`) |
   | `FIREBASE_IOS_API_KEY`, `FIREBASE_IOS_APP_ID` | iOS 앱의 API 키와 앱 ID (`GoogleService-Info.plist`의 `API_KEY`, `GOOGLE_APP_ID`) |
   | `FIREBASE_IOS_BUNDLE_ID` | 등록한 iOS 번들 ID |

   항목별 설명은 [Firebase 설정 안내](app/tool/firebase_setup.md)에 있습니다. `.env`와 앱 구성 파일은 `.gitignore`로 제외되어 있으므로 커밋하지 않습니다.
7. **규칙 검사 (선택):** Python 3, Firebase CLI, Java 21이 있으면 실제 프로젝트 대신 로컬 에뮬레이터로 보안 규칙을 검사할 수 있습니다.
   ```bash
   firebase emulators:exec --only firestore --project demo-do-it-rules "python app/tool/firestore_rules_check.py"
   ```

## 사진으로 할 일 등록
종이 메모를 찍거나 앨범에서 고르면 기기 안에서 글자를 읽어 줄마다 할 일 후보를 만들고, 사용자가 고르고 고친 것만 할 일로 저장합니다.

### 검토 UI 흐름
```
01 할 일 목록 (헤더 카메라) / 02 빈 상태 [사진에서 가져오기]
  └─ 카메라 권한 없음 → 09 권한 안내 ─(허용)→ 06
  └─ 06 메모 촬영: [촬영] 또는 [앨범]에서 한 장
       ├─ 글자를 읽음 → 07 후보 검토: 줄마다 체크·연필로 수정 → [선택한 N개 할 일로 등록]
       │                  → 01 목록 맨 위에 메모 순서대로 추가, '할 일 N개를 추가했습니다.'
       └─ 글자 없음·인식 오류 → 08 인식 실패: [다시 촬영] 또는 [직접 입력으로 등록]
```
- 07에서 뒤로 가면 '인식 결과를 버릴까요?'를 묻습니다. 체크를 모두 풀면 등록 버튼이 꺼집니다.
- 사진으로 만든 할 일은 등록 경로가 `사진에서 가져옴`이고, 사분면은 직접 추가할 때와 같은 기본값(중요·긴급)입니다. 로그인한 상태에서 오프라인이면 MP3와 같이 기기에 먼저 저장되고 `동기화 대기`로 표시됩니다.
- **권한 거부:** 카메라 권한을 거부하면 09가 '사진으로 등록하려면 카메라와 사진 접근이 필요합니다'를 안내합니다. 다시 묻지 않는 거부 상태(Android 두 번 거부, iOS 한 번 거부)면 [설정에서 권한 켜기]가 앱 설정 화면을 엽니다. 설정에서 켜고 돌아오면 09가 '허용됨'으로 바뀝니다. 권한이 없어도 직접 입력으로는 계속 등록할 수 있습니다.
- 앨범은 OS의 사진 선택기로 고르므로 사진 보관함 권한은 묻지 않습니다.

### 원본 사진을 저장하지 않는 방법
- 인식은 기기 안에서만 하고 사진을 서버나 클라우드 AI로 보내지 않습니다.
- 촬영본과 앨범 사본은 받자마자 앱 임시 폴더 `memo_capture/` 한 곳으로 옮깁니다(`app/lib/services/device_memo_scanner.dart`의 `moveToCaptureDirectory`).
- 07·08 화면이 닫히면 그 사진을 지웁니다(`candidate_review_screen.dart`, `recognition_failure_screen.dart`의 `dispose`). 06에서 인식 도중 나가도 지웁니다(`memo_capture_screen.dart`).
- 앱이 도중에 종료돼 남은 파일은 다음에 06을 열 때 `clearLeftovers`가 폴더째 지웁니다.
- 앨범 사진은 크기 옵션 없이 받습니다. Android의 `image_picker`는 크기를 줄여 받으면 원본 사본을 캐시에 따로 남기기 때문입니다.
- 할 일에는 글자만 저장하고 사진 경로나 이미지는 저장하지 않습니다.
- **확인:** 등록하거나 버린 뒤 앱 폴더 전체를 찾아 이미지 파일이 0개인 것을 확인했습니다(Android `run-as`, iOS 시뮬레이터 앱 컨테이너). 자동 테스트 `app/test/services/device_memo_scanner_test.dart`도 임시 폴더로 옮긴 뒤 원래 위치에 남지 않는지, 남은 파일을 지우는지 검사합니다.

### 처리 시간
인식 엔진을 부른 시간(사진 파일 읽기 포함)을 앱이 `[OCR] 인식 Nms, 줄 N개` 로그로 남깁니다. 06 [앨범] 경로로 사진마다 5번 쟀습니다(2026-11-12).

| 기기·OS | 엔진 | 빌드 | 입력 | 평균 | 최대 | 읽은 줄 |
| --- | --- | --- | --- | --- | --- | --- |
| Android 에뮬레이터 Pixel 9 (Android 17, arm64), 비행기 모드 | ML Kit 한국어 | release | 인쇄체 메모 | 122ms | 174ms | 5/5 |
| 〃 | 〃 | release | 손글씨체 메모 | 113ms | 148ms | 3/5 (오타 있음) |
| 〃, 앱을 새로 켠 직후 첫 인식 (4번) | 〃 | release | 인쇄체 메모 | 130ms | 184ms | 5/5 |
| iOS 시뮬레이터 iPhone 17 Pro (iOS 26.5) | Apple Vision | debug | 인쇄체 메모 | 1006ms | 1140ms | 5/5 |
| 〃 | 〃 | debug | 손글씨체 메모 | 1009ms | 1106ms | 5/5 |

- **입력:** 개인정보가 없는 5줄짜리 메모 사진 두 장입니다. 3024×4032 JPEG(1200만 화소, 약 3MB)이고, iOS 사진 선택기를 거치면 약 2.3MB로 다시 저장됩니다. 손글씨체는 사람이 쓴 글씨가 아니라 손글씨 글꼴(나눔손글씨 펜)로 만든 사진입니다. 사진 자체는 제출물에 넣지 않았습니다.
- **기기:** 에뮬레이터·시뮬레이터는 Apple M4 Pro Mac에서 돌렸고, 실기기에서는 재지 않았습니다. iOS 시뮬레이터는 release 빌드를 실행할 수 없어 debug 값입니다.
- 모든 값이 요구사항 B2의 3초 안입니다.
- Android ML Kit은 손글씨체 메모에서 5줄 중 3줄만 읽었고 오타가 있었습니다. 07에서 고치거나 빼고 등록할 수 있습니다.

## 실행
Flutter SDK와 Android 에뮬레이터 또는 iOS 시뮬레이터가 필요합니다. 아래 명령은 저장소 최상위 폴더에서 시작합니다.

### 서버 없이 실행
```bash
cd app
flutter pub get
flutter run
```
Firebase 설정 없이 실행하면 Firebase를 초기화하지 않고 할 일을 기기의 SQLite에만 저장합니다. 이때는 로그인과 서버 동기화를 쓸 수 없습니다.

### Firebase와 함께 실행
1. [백엔드 설정 절차](#백엔드-설정-절차)의 1–5단계대로 Firebase 프로젝트를 준비합니다.
2. `app/.env.example`을 복사해 `app/.env`를 만들고 [6단계](#백엔드-설정-절차)의 표대로 값을 채웁니다. Windows PowerShell에서는 `Copy-Item .env.example .env`를 씁니다.
   ```bash
   cd app
   cp .env.example .env
   ```
3. `.env`를 넘겨 실행합니다.
   ```bash
   flutter pub get
   flutter run --dart-define-from-file=.env
   ```
4. 설정 탭의 [계정 연동]에서 이메일로 가입하거나 로그인합니다. 로그인하면 기기에 있던 할 일이 서버로 옮겨지고, 이후에는 서버와 동기화됩니다.

- 실행할 플랫폼의 값이 일부만 채워져 있으면 앱이 시작되지 않고, 실행한 터미널에 설정 누락 오류가 표시됩니다. Android에서만 실행할 때는 iOS 항목을 빈 문자열로 둬도 됩니다.
- `.env` 값을 바꾼 뒤에는 앱을 완전히 종료하고 다시 실행합니다. 핫 리로드로는 반영되지 않습니다.
- `.env`는 `.gitignore`로 제외되어 있습니다. 설정 값은 코드나 커밋에 넣지 않고 `.env.example`에는 빈 값만 둡니다.

### 두 기기에서 동기화 확인
`flutter devices`로 기기 ID를 확인한 뒤, 터미널 두 개에서 각각 다른 기기로 실행하고 같은 계정으로 로그인합니다.
```bash
flutter run -d <기기 A ID> --dart-define-from-file=.env
```
```bash
flutter run -d <기기 B ID> --dart-define-from-file=.env
```

### 사진 인식 확인
사진 인식은 Firebase 설정 없이 [서버 없이 실행](#서버-없이-실행)으로도 됩니다. iOS는 16 이상, Android는 arm64·x64 기기(대부분의 실기기와 Apple Silicon Mac의 에뮬레이터)에서 동작합니다.

1. **실기기 설치:** 기기를 연결하고 release 빌드로 설치합니다. iOS 실기기는 Xcode에서 `app/ios/Runner.xcworkspace`를 열어 Signing & Capabilities에 본인 팀을 고른 뒤 실행합니다.
   ```bash
   cd app
   flutter run --release
   ```
2. **권한 허용:** 할 일 목록의 카메라 아이콘(할 일이 없으면 [사진에서 가져오기])을 누르면 09 권한 안내가 뜹니다. [권한 허용하기] → OS 창에서 허용합니다. 거부했다면 기기 설정 → 앱 → Do It → 카메라를 켭니다.
3. **비행기 모드:** 제어 센터(iOS)나 빠른 설정(Android)에서 비행기 모드를 켜고 와이파이도 꺼졌는지 확인합니다. 그 상태로 메모를 찍거나 [앨범]에서 고르면 07에 후보가 나오고, 등록하면 목록에 추가됩니다.
4. **처리 시간:** debug나 profile로 실행하면 실행한 터미널에 `[OCR] 인식 120ms, 줄 5개, …` 줄이 찍힙니다. release 빌드는 Android에서 `adb logcat -s flutter`로 볼 수 있습니다.

- 에뮬레이터는 Android Studio의 가상 카메라로 촬영할 수 있고, 메모 사진을 끌어다 놓으면 [앨범]에서 고를 수 있습니다. 비행기 모드는 아래처럼 켭니다.
  ```bash
  adb shell cmd connectivity airplane-mode enable
  ```
- iOS 시뮬레이터에는 카메라가 없어 [앨범]만 쓸 수 있습니다. 사진은 `xcrun simctl addmedia booted <사진 파일>`로 넣습니다.

## 구현 기능
### MP1 — 화면과 상태 관리
- **할 일 목록:** 등록한 할 일을 카드 목록으로 보여 주고, 남은 할 일 개수를 표시합니다.
- **할 일 추가:** [할 일 추가] 버튼으로 입력 시트를 열어 등록합니다. 제목은 필수이며 100자까지 입력할 수 있습니다.
- **완료 토글:** 체크박스를 누르면 완료 상태가 바로 바뀝니다. 완료한 할 일은 취소선으로 표시되고 목록 아래로 내려가며, 남은 개수도 함께 바뀝니다.
- **빈 상태 안내:** 등록한 할 일이 없으면 안내 문구와 등록 방법을 보여 줍니다.

### MP2 — 로컬 저장
- **데이터 유지:** 할 일을 SQLite에 저장해 앱을 다시 켜도 유지합니다.
- **수정·삭제:** 카드를 눌러 연 상세 화면에서 수정하고 삭제합니다. 삭제 전에 확인하며, 삭제 직후 실행 취소할 수 있습니다.
- **필터:** 전체·미완료·완료로 목록을 전환합니다.

### MP3 — 서버 동기화
- **이메일 로그인:** 설정 탭의 [계정 연동]에서 이메일·비밀번호로 가입, 로그인, 로그아웃합니다. 앱을 다시 켜도 로그인이 유지됩니다.
- **첫 로그인 이관:** 로그인 전에 SQLite에 저장한 할 일을 첫 로그인 때 같은 ID로 서버에 한 번 옮깁니다. 이후에는 Firestore와 기기의 오프라인 캐시만 사용합니다.
- **다른 기기 반영:** 한 기기에서 추가·수정·완료·삭제하면 같은 계정의 다른 기기 목록에도 반영됩니다. 목록을 아래로 당기면 서버에서 다시 받아 옵니다.
- **오프라인 작성:** 인터넷이 끊기면 목록 위에 오프라인 배너가 뜹니다. 그동안 작성·수정한 할 일은 기기에 먼저 저장되고 `동기화 대기 N`으로 표시되며, 연결이 돌아오면 자동으로 서버에 반영되어 `동기화 완료`로 바뀝니다.
- **확인:** Android 에뮬레이터 두 대에서 확인했고, 장면별 사진은 [`screenshots/mp3/`](screenshots/mp3)에 있습니다. iOS에서의 동기화는 아직 확인하지 않았습니다.

### MP4 — 온디바이스 AI로 종이 메모 가져오기
- **사진 → 후보 → 선택 저장:** 메모를 찍거나 앨범에서 한 장 고르면 기기 안에서 글자를 읽어 줄마다 후보를 보여 줍니다. 필요한 후보만 체크하고 문장을 고쳐 등록하면 메모 순서대로 목록 맨 위에 추가됩니다. 자세한 흐름은 [사진으로 할 일 등록](#사진으로-할-일-등록)에 있습니다.
- **오프라인 인식:** Android는 ML Kit 한국어 번들 모델, iOS는 Apple Vision으로 비행기 모드에서도 인식합니다.
- **원본 사진 미저장:** 사진은 등록하거나 버리면 바로 지우고, 할 일에는 글자만 남깁니다.
- **권한 거부 안내:** 카메라 권한이 없으면 09에서 이유를 설명하고, 다시 묻지 않는 거부 상태면 앱 설정으로 보냅니다.
- **확인:** Android 에뮬레이터(release, 비행기 모드)와 iOS 시뮬레이터에서 확인했고, 사진은 [`screenshots/mp4/`](screenshots/mp4)에 있습니다. 실기기 확인은 아직 하지 않았습니다.

### 그 밖의 할 일 기능
- **상세 화면:** 마감일, 남은 기간, 등록 경로, 상태를 보여 주고 수정, 완료 표시, 삭제를 할 수 있습니다.
- **사분면 보기:** 할 일 탭 안에서 목록과 사분면 보기를 전환합니다. 카드를 길게 눌러 다른 영역으로 끌면 중요도와 긴급도가 바뀝니다.

### 아직 연결되지 않은 부분
- 일정·팀 탭은 화면이 먼저 만들어져 있고, 할 일 데이터와 서버에는 아직 연결되어 있지 않습니다. 설정 탭은 계정 연동(가입·로그인·로그아웃)만 서버에 연결되어 있습니다.
- 팀 공유와 회원 탈퇴 시 서버 데이터 삭제는 아직 구현하지 않았습니다.
- 인식한 문장에서 마감일을 뽑는 기능과 클라우드 AI로 결과를 다듬는 기능은 아직 없습니다.
- 메모 촬영 화면을 연 채 앱을 백그라운드로 보냈다 돌아올 때 카메라를 다시 켜는 처리는 아직 없습니다.
- 마감 알림은 켜고 끄는 값만 저장하며, 실제 알림은 아직 예약하지 않습니다.

| 이메일 로그인·가입 | 이메일·비밀번호 입력(가입할 때는 비밀번호 확인 추가)과 로그인·가입 전환. 잘못된 비밀번호, 이미 가입한 이메일, 네트워크 오류를 안내합니다. |

### 규칙
- 새 화면은 `screens/<화면이름>/<화면이름>_screen.dart`로 만들고, 클래스 이름은 `XxxScreen`으로 합니다.
- 한 화면에서만 쓰는 위젯은 그 화면 폴더의 `widgets/`에, 두 화면 이상에서 쓰면 `lib/widgets/`로 옮깁니다.
- 파일 이름은 `snake_case.dart`, 클래스 이름은 `PascalCase`로 씁니다.
- 화면 단위로 작업을 나누면 서로 다른 파일을 수정하게 되어 머지 충돌이 줄어듭니다.
- `app.dart`, `core/` 같은 공용 파일을 수정할 때는 팀원에게 먼저 알립니다.
