# 이메일 계정 연동 확인 (#76)

## 준비

- #75의 Android 또는 iOS Firebase 설정을 로컬 `.env`에 입력한다.
- Firebase 콘솔 Authentication에서 이메일/비밀번호 제공업체를 활성화한다. 이메일 링크 로그인은 사용하지 않는다.
- 새 패키지는 추가하지 않는다. #75의 `firebase_auth`를 사용한다.

```powershell
flutter run --dart-define-from-file=.env
```

## 실제 앱 확인

1. 하단 설정 → 계정 연동 → 새 계정 만들기를 연다.
2. 본인이 관리하는 테스트 이메일과 비밀번호·확인 입력으로 가입한다.
3. 설정 화면으로 돌아와 연동됨 표시와 가입한 이메일을 확인한다.
4. 앱을 완전히 종료하고 같은 명령으로 다시 실행한다. 같은 계정의 이메일과 연동 상태가 유지되는지 확인한다. 단순 hot reload는 재시작 확인에 해당하지 않는다.
5. 로그아웃 확인에서 취소하면 상태를 유지하는지, 확인하면 미연동 상태가 되는지 확인한다.
6. 계정 연동에서 기존 계정으로 로그인한다. 잘못된 비밀번호는 오류를 표시하고 올바르게 고치면 로그인되는지 확인한다.
7. 이미 가입한 이메일로 다시 가입하면 중복 이메일 안내가 나오는지 확인한다.
8. 기기의 네트워크를 끄고 로그인을 요청한다. 실패 안내 후 연결을 복구하고 수동으로 다시 로그인되는지 확인한다. SDK의 네트워크 실패 판정에는 시간이 걸릴 수 있다.
9. 로그인 화면에서 뒤로 가면 연동 성공 안내 없이 미연동 상태를 유지하는지 확인한다.

## 자동 검증

```powershell
flutter analyze
flutter test
```

인증 인터페이스에 가짜 서비스를 주입해 가입·로그인·로그아웃·취소·오류·중복 제출·복원된 계정 표시를 검증한다. 실제 Firebase의 디스크 로그인 유지와 서버 오류는 위의 실제 앱 확인으로 별도 검증한다.

## 범위

- Firebase Auth가 Android·iOS의 로그인 세션을 관리한다. 앱에서 비밀번호를 SQLite나 `.env`에 저장하지 않는다.
- Firebase 설정 없이 실행하면 기존 설정 화면을 사용하고 인증은 연결하지 않는다.
- 이번 단계는 계정 인증만 연결한다. SQLite 할 일은 그대로 유지한다. 로그인 시 기존 할 일의 Firestore 이관과 계정별 저장소 전환은 #77에서 구현한다.
- 닉네임 서버 저장, 팀 공유와 계정·할 일 전체 삭제는 이번 구현 범위에 포함하지 않는다. 서버에 연결하지 않은 기능을 성공으로 처리하지 않는다.
- 이 화면은 #76에 명시된 이메일·비밀번호 방식으로 추가했다. 기존 공용 디자인 토큰을 사용하며, `MainScreen`의 설정 탭 연결 변경은 PR에서 팀원 리뷰를 요청한다.
